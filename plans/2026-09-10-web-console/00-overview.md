# Web 远程控制台 — 总览

> 状态：`[planned]`
> 提出时间：2026-09-10

## 需求

用户原话：

> 我们还需要一个 tab 叫 Web，Web 应该是在设置之前，就是可以把我们这个应用给一个端口，
> 自己映射一个网址，但是这个端口不会在映射 tab 显示，是特别端口，只在这里显示。
> 然后我们需要给它设置一个访问 token，然后它可以有备注，来备注信息。
> 这样用户可以在手机或其他设备上使用本机这个 easy port，进入该页面需要访问 token。

拆解为四件事：

1. 应用内嵌一个 HTTP 服务，监听本机某个端口，提供一套 Web 界面
2. 用现有的 cloudflared 能力把该端口映射出去，拿到公网 URL
3. 这条映射是**特别端口**：不出现在映射 tab，只在 Web tab 管理
4. 访问需要 token；支持备注

## 这个功能与之前所有功能的本质区别

**之前映射的是用户自己的服务，这次映射的是 Easy Port 自己的控制面。**

谁拿到这个 URL + token，谁就能在用户的机器上开关任意端口的公网映射——
等于把一个远程控制入口挂到公网上。Quick Tunnel 的域名虽然是随机的，
但**它不是密钥**：会出现在 Cloudflare 边缘日志里，用户也可能截图、粘贴给别人。

因此 token 必须是真正的认证凭据，而不是「再加一道随机数」。
安全设计见 [02-security](./02-security.md)，那一卷的每条措施都不是可选项。

## 与项目不变量的关系

### 不变量 2 需要改写

现文：「**不引入 Express**：进程管理属于 Rust 侧职责，不额外拉起 Node 进程。」

本功能要在 Rust 侧内嵌 HTTP 服务（axum）。严格说不违反字面——仍然不拉起 Node
进程——但它确实新增了一个此前没有的能力面，原文的语境不覆盖这种情况。

**建议改写为**：不引入独立的后端进程；如需 HTTP 服务，只能是 Rust 侧进程内的
内嵌服务，且必须能随应用退出而关闭（不变量 5 的延伸）。

改不变量需用户确认，见下方「待确认」。

### 不变量 5（进程不可泄漏）的延伸

内嵌服务不是子进程，但同样必须有确定的关闭路径：应用退出、用户手动关闭、
端口冲突失败，三条路径都要能干净地停掉监听并释放端口。
axum 用 `with_graceful_shutdown` + 一个 `oneshot`/`watch` 信号实现。

### 不变量 6（链接即敏感信息）适用且加强

Web 控制台的 URL 同样不落盘、不进日志。**token 更要如此**——
它落盘是必要的（否则每次重启都要重新配），但：

- 只存**哈希**，不存明文（见 02-security）
- 绝不出现在日志、错误信息、导出的文档里
- 界面上默认打码，点击才显示

## 待确认（动工前需要用户拍板）

1. **改写不变量 2** —— 允许 Rust 进程内的内嵌 HTTP 服务。
2. **Web 端的权限范围**：手机上能做的事应该到哪一步？
   - A. 只读：看有哪些映射、链接是什么、复制链接（最安全）
   - B. 只读 + 开关已有映射（推荐：覆盖「人在外面，想把某个服务打开」的主要场景）
   - C. 完整控制：还能新建任意端口的映射、改配置
   C 的风险明显更高——攻破 token 等于拿到机器上任意端口的对外暴露能力。
   我倾向 **B**。
3. **Web 控制台自身要不要支持 `auto_start`**（开机自动把控制台也映射出去）。
   便利但危险：意味着开机即在公网挂一个控制入口。
   我倾向**默认关闭**，且开启时在界面上给一次明确警告。

## 验证方式

- Rust 侧单元测试：token 哈希与校验、限速计数、特别端口不进普通列表
- 集成测试：起服务 → 未带 token 应 401 → 带错 token 应 401 且计入限速 →
  带对 token 应 200 → 关闭后端口应释放
- 手动验收：手机连公网 URL，走一遍登录与操作
