# 安全设计

> 状态：`[planned]`
> **本卷的每一条都不是可选项。** 实现时若要省略其中任何一条，先与用户确认。

## 威胁模型

先说清楚在防谁：

| 资产 | 威胁 | 后果 |
|---|---|---|
| 控制台的公网 URL | 出现在 Cloudflare 边缘日志、被用户截图 / 转发 | URL 本身**不能当密钥**用 |
| 访问 token | 弱口令被猜、被暴力枚举、被日志泄漏 | 攻击者获得本机端口的对外暴露能力 |
| 会话 cookie | XSS 窃取、CSRF 借用 | 同上 |
| 内嵌服务本身 | 路径穿越、请求体炸弹 | 读到任意文件 / 内存耗尽 |

**最坏情况**：攻击者拿到控制权后，可以把用户本机的数据库、管理后台映射到公网。
这比「某个已映射服务被访问」严重一个量级，因此防护标准要按「远程控制入口」来定，
不能按「一个小工具的可选功能」来定。

## token

### 生成：密码学随机，不让用户自己设

```
32 字节 CSPRNG（getrandom / OsRng）→ base64url 无填充 → 43 字符
```

**不提供「自定义 token」入口。** 用户自己设的密码几乎必然弱于随机串，
而这个入口的价值（好记）远低于风险。用户想要「好记」应该用密码管理器。

生成的明文**只在生成那一刻返回一次**，之后无法再查看，只能重新生成。
界面上明确写这一点，并提供「复制」按钮。

### 存储：只存哈希

`state.json` 只存哈希，不存明文。理由：`state.json` 是明文 JSON，
用户可能备份、同步到网盘、贴进 issue 求助。

哈希算法用 **Argon2id**（`argon2` crate），不是 SHA-256：
- token 虽是高熵随机串，但慢哈希是几乎零成本的额外保险
- 一次校验几十毫秒，对每分钟个位数的登录频率毫无影响

> 若为控制依赖数量而选 SHA-256，必须至少加盐，**并在此处写明降级理由**。
> 高熵随机 token 用 SHA-256 在密码学上可接受，但没有理由省这一个依赖。

### 校验：常数时间比对

用 `subtle::ConstantTimeEq` 或 argon2 自带的 `verify_password`
（后者内部已是常数时间）。**绝不能用 `==` 比对哈希字符串**——
逐字节短路会泄漏前缀匹配长度，配合可重复请求足以逐位还原。

## 会话

登录成功后签发 session，而不是每次请求都带 token：
减少 token 在网络上重复出现的次数。

Cookie 属性，一个都不能少：

| 属性 | 值 | 理由 |
|---|---|---|
| `HttpOnly` | 是 | JS 读不到，XSS 也偷不走 |
| `Secure` | 是 | 只走 HTTPS。cloudflared 提供的就是 HTTPS |
| `SameSite` | `Strict` | 防 CSRF。控制台没有跨站跳转需求 |
| `Max-Age` | 12 小时 | 手机上不必频繁重登，但也不无限期 |
| `Path` | `/` | — |

session 存在内存里（`HashMap<SessionId, Instant>`），**不落盘**：
应用重启后重新登录是可接受的代价，换来的是重启即失效的确定性。

SessionId 同样是 32 字节 CSPRNG。

## 限速

登录接口必须限速，否则 43 字符的 token 虽然枚举不完，
但攻击者可以用请求把服务打满（等效 DoS）。

```
按 IP 计数，滑动窗口：连续 5 次失败 → 该 IP 锁定 15 分钟
全局兜底：每分钟最多 30 次登录尝试
```

**注意**：经 cloudflared 转发后，`remote_addr` 是隧道本地地址，
真实来源在 `CF-Connecting-IP` 头里。但该头**可被伪造**（如果有人直接访问本机端口），
因此：
- 取 IP 用于限速时，优先 `CF-Connecting-IP`，但同时保留全局兜底计数
- 全局兜底不依赖任何请求头，是伪造 IP 绕不过去的那道闸

失败响应统一为 401 + 固定文案，**不区分「token 错误」与「已被限速」**——
区分了等于告诉攻击者「这个 token 前缀对了」或「换个 IP 继续」。

## 暴露面收敛

Web 端只暴露**必要**的操作，不是把桌面端的 19 个 command 全代理出去。

按 00-overview 待确认项 2 的方案 B（推荐）：

| 允许 | 不允许 |
|---|---|
| 列出映射、查看链接 | 新建任意端口的映射 |
| 开关**已有**映射 | 修改 / 删除记录 |
| 复制链接 | 改 Web 控制台自身的配置（端口 / token / 自启） |
| — | 归档、清空历史、改标签备注 |

**控制台不能改自己**：否则攻破一次即可把 token 改成攻击者的，永久驻留。
所有涉及控制台自身配置的操作，只能在桌面端做。

## 其他必须项

- **静态资源不走文件系统路径拼接**：Web UI 用 `include_dir!` 编进二进制，
  按固定映射表取，从根上杜绝路径穿越。见 03-web-ui。
- **请求体上限**：登录接口 `1 KB` 足够，用 `DefaultBodyLimit` 卡死。
- **安全响应头**（`tower-http::set_header`）：
  `Content-Security-Policy: default-src 'self'`、`X-Content-Type-Options: nosniff`、
  `Referrer-Policy: no-referrer`、`X-Frame-Options: DENY`。
- **日志**：token、session id、公网 URL 一律不进日志（不变量 6）。
  错误信息里也不能回显用户提交的 token。
- **默认关闭**：控制台默认不开启、`auto_start` 默认关闭。
  开启 `auto_start` 时界面必须给一次明确警告：这意味着开机即在公网挂控制入口。

## 界面上的诚实告知

桌面端 Web tab 必须常驻一句说明，而不是藏进帮助文档：

> 开启后，任何拿到链接**并知道 token** 的人都能远程开关你的端口映射。
> token 请当作密码保管，不要和链接一起发给别人。

理由与底栏的安全提示一致：这个功能的风险高于普通映射，用户必须在开启前就知道。

## 验收标准

- [x] token 为 32 字节 CSPRNG，界面无「自定义 token」入口
- [x] `state.json` 中搜不到 token 明文（只序列化 `token_hash`，`console.rs` 单元测试覆盖）
- [x] 校验走常数时间比对 —— `Argon2::verify_password`，`auth.rs` 单元测试覆盖
- [x] 未登录访问任意受保护路由 → 401 —— `web_console.rs::未登录访问受保护接口一律_401`
- [x] 错 token 5 次 → 该 IP 被锁，且响应与「token 错误」不可区分 —— `错误_token_被拒且响应与限速不可区分`、`限速期间即使_token_正确也不放行`
- [x] 伪造 `CF-Connecting-IP` 绕过 IP 锁后，仍被全局兜底拦住 —— `auth.rs::全局兜底能拦住伪造来源的枚举`
- [x] cookie 四个属性齐全 —— `正确_token_能登录且_cookie_属性齐全`
- [x] 应用重启后旧 session 失效（会话只在内存，进程退出即消失）；换 token 亦立即踢线 —— `重新生成_token_后旧会话立即失效`
- [x] Web 端调用桌面端「不允许」清单里的操作 → 404（这些路由根本不存在，不是靠运行时判断拦的）
- [x] 日志与错误响应中不出现 token / session id / 公网 URL —— 失败响应固定为 `{"error":"认证失败"}`

## 明确不做

- **不做多用户 / 多角色**：单机工具，一个 token 一种权限，多余的复杂度是负债。
- **不做 token 有效期**：手动重新生成即可，自动过期会在用户最需要时把人锁在外面。
- **不做 IP 白名单**：手机在移动网络下 IP 经常变，白名单会让功能不可用。
