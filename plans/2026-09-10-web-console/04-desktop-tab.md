# 桌面端 Web tab

> 状态：`[planned]`

## 位置

侧栏顺序：**映射 → 历史 → Web → 设置**（按用户要求，Web 在设置之前）。

`Page` 类型加 `"web"`，`ITEMS` 插在 `history` 与 `settings` 之间。
图标用 `Globe` 或 `MonitorSmartphone`——后者更能表达「在别的设备上用」，
但要确认 lucide 里存在（同 `Repeat` 那次的教训：先查 `node_modules`）。

## 页面内容

### 常驻风险说明（置顶，不可折叠）

> 开启后，任何拿到链接**并知道 token** 的人都能远程开关你的端口映射。
> token 请当作密码保管，不要和链接一起发给别人。

用 `ShieldAlert` + `status-pending` 色，与底栏安全提示同一套视觉语言。
**不做成可关闭的提示**：这个风险在每次开启前都值得再看一眼。

### 配置区

| 项 | 控件 | 约束 |
|---|---|---|
| 监听端口 | `NumberField` | 仅未运行时可改；与已有映射冲突时即时提示 |
| 备注 | `LabelEditor` 或普通输入框 | 随时可改 |
| 访问 token | 见下 | — |
| 开机自动开启 | `Switch` | 默认关；开启时弹一次确认 |

### token 区

三种状态：

1. **未设置**：显示「尚未设置 token，开启前必须先生成」+ 生成按钮。
   此时开启按钮 disabled，tooltip 说明原因（用 `<span>` 包裹，
   disabled 元素收不到指针事件——上次踩过）。
2. **刚生成**：明文显示 + 复制按钮 + 一句「只显示这一次，请立即保存」。
3. **已设置**：显示 `已设置 ••••••••` + 「重新生成」按钮。
   **不提供查看入口**——哈希不可逆，界面上也不该假装能看。

重新生成要二次确认：旧 token 立即失效，已登录的设备会被踢下线。

### 运行区

未运行：一个「开启」按钮。
运行中：
- 公网链接（可点开 / 复制，复用 `tunnel-card` 的交互）
- 一个「关闭」按钮（destructive + 二次确认）
- 状态指示（复用 `statusMeta` 的圆点语言）

**链接与 token 分开展示，中间留出视觉间隔**，并在复制链接的 tooltip 里
提示「链接不含 token，可以单独发送」——引导用户分渠道传递。

## 与现有组件的复用

能复用的：`NumberField`、`Switch`、`Hint`、`Button`、`Card`、`statusMeta` 的配色。
不复用 `TunnelCard`：控制台的字段与操作都不同，强行复用会让那个组件长出
第三个 variant，把它推向不可维护。

## 状态获取

`useWebConsole()` hook，`refetchInterval: 3000`，与其他轮询一致。
`WebConsoleView` 不含 token 哈希，只含 `hasToken: boolean`。

## 验收标准

- [x] 侧栏顺序为 映射 / 历史 / Web / 设置
- [ ] 未设 token 时开启按钮不可用，且能看到原因
- [x] 生成的 token 明文只出现一次；刷新页面后变为「已设置」—— 明文只存在于组件 state，`WebConsoleView` 只带 `hasToken`
- [x] 重新生成后，Web 端已登录的设备下次请求即被拒 —— `重新生成_token_后旧会话立即失效`
- [x] 端口与已有映射冲突时，开启前就给出提示 —— 校验在 `set_web_console_port`，保存端口那一步就拦下
- [ ] 运行中关闭应用 → 重启后控制台为关闭态（除非开了 auto_start）
