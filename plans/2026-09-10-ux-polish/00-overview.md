## 范围与边界

**本计划不增加功能**，不引入新的穿透能力、新的 provider、新的数据类型或新的持久化字段。
只针对**已有的映射 / 断开 / 计数 / 自动重连 / 错误提示**这几件事，改善其表达方式与交互反馈。

判定一条改进是否属于本计划的标准：

| 属于 | 不属于 |
|---|---|
| 把已有信息说得更清楚 | 展示新采集的信息 |
| 把已有操作变得更好点 | 新增一个操作入口 |
| 把已有等待过程可视化 | 改变等待本身的实现 |
| 补齐已有交互的缺失反馈 | 引入新的交互范式 |

一条例外：`03-window-and-shell.md` 里的「窗口尺寸记忆」需要落盘一个字段。
它被归入本计划是因为纯粹服务于「不要每次都手动调窗口」这一体验，且复用现有 `state.json`。
**若你认为这已越界，可单独砍掉该条，不影响其余项。**

本计划所有条目均**不触碰**以下已定型的决策：

- 不引入新依赖除非分册中显式说明并给出理由（当前仅 03-2 可能需要 `tauri-plugin-window-state`，已标注为可选）。

### 用户验收发现的缺陷（已修）

**Switch 组件完全不可用**——用户反馈开关按不动，界面上只是一个黑色圆点。

根因：`scripts/fetch-shadcn.mjs` 从 registry 取到的 `switch.tsx` 用了
`data-checked:` / `data-unchecked:` 变体，但 Radix 实际渲染的属性是
`data-state="checked" | "unchecked"`；同时滑块依赖 `group-data-[size=…]/switch:`
具名 group 变体，在本项目 Tailwind 4 配置下**未生成任何 CSS**。
两者叠加的结果是：轨道无背景色、滑块无尺寸也不位移，既看不出状态也没有可点击的视觉区域。

验证方式：编译后的 CSS 中 `[data-checked]` 选择器存在但永不匹配，
`data-state` 选择器则完全不存在。修复后二者反转（`[data-state=checked]` 已生成）。

修复：改用标准 `data-[state=…]` 选择器并固定滑块尺寸，已在
`src/components/ui/switch.tsx` 顶部注释说明「勿改回 registry 原版」。

> **对 `fetch-shadcn.mjs` 使用者的提醒**：registry 源码不保证与本项目的
> Tailwind 配置兼容，取下来后需实际验证渲染效果，不能只看编译是否通过——
> 本例中 `tsc`、`oxlint`、`vite build` **全部通过**，缺陷只在真实界面里可见。

同时修了标签文案：「开机重建」用户看不懂（误以为与 Windows 开机有关），
改为「下次启动时自动映射」，并在 tooltip 里补上「会分配新链接」的后果说明。

### 一处超出原计划的改动

原计划 2-1 打算把超时文案写成固定的「30 秒」。实现时发现这会与
`cloudflared.rs` 的 `URL_TIMEOUT` 常量形成两处硬编码，改了常量就会漏改文案。
故把 `TunnelError::UrlTimeout` 改为携带 `u64` 秒数，并新增
`url_timeout_secs` command 供前端等待提示引用，配一条单元测试守护一致性。
代价是新增了一个 command（第 11 个），但避免了必然发生的文案漂移。
